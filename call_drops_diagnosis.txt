================================================================
ISSUE A, Media Stream WebSocket fails (the actual drop cause)
================================================================
Error code: 31921 ("Stream, Connection error")
Source: tools/llm_proxy/voice_routes.py:146 (WS /twilio/stream)

What's happening:
  1. POST /twilio/voice succeeds → returns <Connect><Stream> TwiML
  2. Twilio opens WS to /twilio/stream
  3. Handshake or first-frame exchange fails on cold path
  4. Twilio falls through to its error path → 3 beeps + "we're sorry"

What it's NOT:
  - Not Twilio routing (call reaches the app per /healthz being 200)
  - Not the second Fly project (failures occurred after removal too)
  - Not /twilio/voice timing out (that would be error 11200, not 31921)
  - Not a missing route, voice_router is mounted in main.py:320

What it likely IS:
  - Upstream WebSocket cold start (Deepgram / Cartesia) takes too long
    on the FIRST call after idle, exceeding Twilio's media-stream
    setup tolerance
  - shared-cpu-1x / 1 GB is thin for the Pipecat pipeline's startup
  - In-memory pending_calls bridge (voice_routes.py:189) is FINE in
    steady state but would be lost on any restart, not the issue
    here, since /healthz shows the process is up
  - Possible asyncio event-loop starvation during pipeline init on
    cold path

================================================================
ISSUE B, /twilio/status returns 404 (noise, not a drop cause)
================================================================
Error code: 15003, every call generates one (13/13)
Verified locally: curl https://clearslope-receptionist.fly.dev/twilio/status → 404
Verified in code: no /twilio/status route defined in
                  tools/llm_proxy/voice_routes.py or main.py

Twilio is posting status callbacks to a URL that doesn't exist.
This happens AFTER the call so it can't cause the drop, but it's
noise in the Debugger and should be fixed:
  Option 1 (cheap): add a no-op route:
    @router.post("/twilio/status")
    async def twilio_status(): return Response(status_code=204)
  Option 2: clear the statusCallback URL on the Twilio number
            config (Twilio Console → Phone Numbers → Voice config)
