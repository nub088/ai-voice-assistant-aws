<objective>
Wire the registry. Convert the per-tenant TODOs in `sheets_writer.py` and `sms_notifier.py` into prefix-keyed factories. Replace the single-client startup block in `main.py` (lines 156-196) with a loop that builds one `ClientContext` per JSON in `config/clients/`. Stash the registry, the in-memory minute counters, and the ephemeral call-sid → twilio-number bridge map on `app.state`.

After this plan, the app loads but no inbound webhook code path uses the registry yet, Plan 03 cuts over `voice_routes.py`. This plan is the seam: existing single-client code paths are removed; new dict-keyed access patterns are in place.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Env vars → app | Per-client `{PREFIX}_*` env vars consumed by per-client factories. Missing vars must NOT silently fall back to a sibling tenant's vars |
| Filesystem → app | `config/clients/*.json` loaded at startup; one bad file fails the whole boot (intended) |
| App.state → request handlers | Mutable shared state read by every voice request; no per-request locking needed (dict reads/writes are thread-safe in CPython at the granularity used) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02-01 | Information Disclosure | Env var prefix bleed (e.g. ALLGREEN_GOOGLE_SHEET_ID unset → factory falls back to GOOGLE_SHEET_ID and writes All Green calls into Clear Slope's sheet) | mitigate | writer_from_env(prefix) ONLY reads `f"{prefix}_GOOGLE_SHEET_ID"`, no bare-name fallback; if unset, returns None and main.py logs a per-client warning. Same for notifier_from_env. Confirmed by grep: zero references to bare `os.environ.get("GOOGLE_SHEET_ID"` after this plan |
| T-01-02-02 | Tampering | Two clients whose env_prefix expands to the same env var by typo | mitigate | env_prefix uppercase-alphanumeric guard from Plan 01 covers this; main.py also logs `client=%s prefix=%s` so prefix collisions are visible at boot |
| T-01-02-03 | Information Disclosure | Per-client SmsNotifier inheriting wrong business_name (caller of client A gets text "thanks for calling Client B") | mitigate | notifier_from_env is called WITH the per-client config's business.name and business.short_name; templates interpolate from instance state, never globals |
| T-01-02-04 | Denial of Service | One bad JSON crashes startup | accept | Fail-fast at boot is intentional, better than serving traffic with a broken tenant. Healthz returns 503 anyway |
| T-01-02-05 | Spoofing | Stale `app.state.loaded_prompt` / `sheets_writer` / `sms_notifier` accidentally referenced by leftover code | mitigate | This plan deletes those attributes entirely; any stale reference becomes an AttributeError at request time (loud failure). Verified by grep, see acceptance criteria |
</threat_model>

       # Multi-client registry. Drop a config/clients/<id>.json file + set
       # {PREFIX}_* env vars, then restart to onboard a new client (D-02, D-05).
       client_configs = scan_client_configs(Path("config/clients"))

       global_auth_token = os.environ.get("TWILIO_AUTH_TOKEN", "").strip()

                           cfg.client_id, cfg.env_prefix,
